# Hanzi Burst — browser extension (Chrome, Firefox)

Select Chinese text on any page → card with pinyin, meaning and the character's components. Japanese text (kana in the
selection, or `lang="ja"` on the page) → words with kana reading, romaji/Cyrillic, dictionary form, and on/kun readings
of each kanji (`site/ja.js` runs in the background worker over the JMdict shards). Fully offline.

Modes: selection, hover, Alt + hover; right-click menu on a selection. "Pinyin / furigana above the text" (popup, or per tab
from the page context menu) wraps Chinese text nodes in `<ruby>`: `annotate` in background.js splits by the longest
CC-CEDICT word and spreads its syllables over the characters; Japanese text (kana, or `lang="ja"`) gets furigana: `JA.analyze`
from ja.js splits it into JMdict words and `furi` puts each reading over its kanji runs (見せて → 見: み); up to 5000 text nodes per page.

Build (needs `site/data/`, which is generated by the site build):

    python3 scripts/build_extension.py --zip

Then load `extension/` via chrome://extensions → Developer mode → Load unpacked.
Firefox: `site/hanzi-burst-firefox.zip` (same code, `background.scripts` + gecko id `hanzi-burst@lipu.dev`) →
about:debugging → Load Temporary Add-on (unsigned zips only load temporarily). The signed build comes from addons.mozilla.org:
listing `hanzi-burst` (0.2.6 submitted 2026-11-13, in review); new versions are submitted by CI on a `v*` tag
(`extension-release.yml`, job `firefox`; see the root README, «Выпуск новой версии расширения»).

Store summary = manifest `description` (`__MSG_extDescription__`, `_locales/{en,ru}/messages.json`, max 132 chars);
the long description and permission justifications live in `store/LISTING.md`. Third-party data credits: `NOTICE.txt`.
`extension/data/`, `extension/icons/` and `extension/ja.js` are generated and git-ignored.

The zip is also built by every site deploy (`scripts/build_all.sh`) and served at
https://hanzi.lipu.dev/hanzi-burst-extension.zip. To release a new version to the Chrome Web Store,
bump `version` in `manifest.json`, merge to `main`, then push tag `v<version>`: see the root README, section «Выпуск новой версии расширения».

"My characters" (learned.html) shows progress by HSK 3.0 level from `data/hsk.json` (copied from `site/data`); click a level
to list the characters of that level not marked yet.

Known characters (`chrome.storage.local` `known`) are merged both ways with the site's list (`localStorage` `hanzi-known`)
by the content script on hanzi.lipu.dev: on page load, when the extension's list changes, when the site saves its list (`hanzi-known-saved` event) and when the tab is hidden.
`knownBase` holds the list after the last merge, so a character unmarked on one side is removed on the other too.
A missing site list is not taken as "everything unmarked": if `hanzi-known` is absent (site data cleared, incognito)
or none of `knownBase` is left in it, the lists are united and nothing is deleted (except a one-character `knownBase`
right after the site saved its list: the user unmarked the last character). See the comment above `syncSite` in `content.js`; the function is `mergeKnown` in `common.js` (tested in `tests/js`).
The site listens for the `hanzi-known` window event to reload its list.
